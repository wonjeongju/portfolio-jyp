매번 새로 하지 않도록, 구조를 먼저 만듭니다

분석 → 초안 → 검토 → 수정. 반복되는 문서 작업을 4단계로 나누고, 품질 기준을 먼저 정의했습니다.

파이프라인 설계 품질 게이트 문서 자동화

왜 나눴나

한 번에 요청하면 결과가 들쭉날쭉했습니다. 어느 지점에서 무너지는지 확인하고, 판단이 필요한 곳마다 끊었습니다.

가장 먼저 만든 건 프롬프트가 아니라 채점 기준이었습니다. 무엇이 좋은 결과인지 정의하지 않으면 고칠 수도 없습니다.

품질 기준

12개 기준을 3층으로 나눴습니다.

  • 1층 · 거를 이유 제거 동문서답 없음 · 형식 무결 · 근거 없는 주장 없음 · 과장 없음
  • 2층 · 뽑을 이유 생성 스왑 테스트 · 10초 테스트 · 상대 관점 · 면접 질문 유발 · 한 사람으로 읽힘
  • 3층 · 독자 적합 비전문가 이해 가능 · 키워드 가시성

50점 만점으로 채점하고, 44점 미만이면 수정 후 재검토합니다. 최대 2회.

각 단계

① ANALYSIS · 분석대상을 조사하고, 요구 역량을 뽑고, 가진 경험 중 무엇을 쓸지 고르고, 어디에 배치할지 설계합니다.

② DRAFT · 초안분석 결과만 보고 씁니다. 흐름에만 집중합니다.

③ REVIEW · 검토새로 쓰지 않고 진단만 합니다. 12기준으로 채점하고 수정 우선순위를 정합니다.

④ REFINE · 수정검토를 반영해 고치고, 완성되면 자동으로 저장합니다.

옮기면

첫 적용은 지원 문서 작성이었습니다. 구조는 그대로 옮겨집니다.

  • 대상 조사 → 클라이언트 · 브랜드 사전 리서치
  • 요구 역량 추출 → 브리프 해석 · 핵심 요구 정리
  • 경험 매핑 → 레퍼런스 · 사례 라이브러리에서 선택
  • 12기준 채점 → 제안서 · 크리에이티브 리뷰 기준
  • 44점 게이트 → 내부 검수 통과 기준
